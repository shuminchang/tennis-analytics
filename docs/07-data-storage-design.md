# 資料保存與品質設計

狀態：設計中，尚未建立業務資料表或匯入資料。

## 保存原則

1. 原始 CSV 保持不變，記錄來源 Git 快照與檔案雜湊。
2. 匯入紀錄可追溯至來源檔案及資料紀錄序號（不含標頭）。
3. 轉換為正式欄位時，不能遺失無法解析或有疑義的原值。
4. 缺值不自動補零；有效零值與缺值分開。
5. 品質問題保存原因及影響範圍：
   - 欄位問題：只影響使用該欄位的指標。
   - 身分問題：可能影響整場個人勝負、H2H 與 Elo。
6. 賽事納入範圍與資料品質分開記錄。
7. 排名內容衝突保留整組來源，不任意選第一筆或最後一筆。
8. 保存所用規則的版本，讓後續修正與重新計算可追查。

## 球員欄位對照（設計草案）

每位球員以 (tour, player_id) 識別，不以姓名合併。
原始值由來源紀錄保存；具體保存表結構尚待設計。

| 來源欄位 | 正式欄位 | 型別方向 | 轉換與品質規則 |
| --- | --- | --- | --- |
| 檔案所屬 atp/wta | tour | varchar(3) | 轉為 ATP/WTA，必填 |
| player_id | player_id | integer | 正整數，必填；無效時隔離來源紀錄，不自行產生替代 ID |
| name_first | name_first | text | 空字串轉 NULL；保留拼寫，不用姓名推斷身分 |
| name_last | name_last | text | 空字串轉 NULL；保留拼寫，不用姓名推斷身分 |
| hand | hand | char(1) | 保留 R/L/U/A；空字串轉 NULL；其他值轉 NULL，保留來源原值並記錄品質問題 |
| dob | dob | date | 有效 YYYYMMDD 轉日期；空字串轉 NULL；非空無效值轉 NULL 並記錄品質問題 |
| ioc | ioc | varchar(3) | 三個大寫英文字母可保存；空字串轉 NULL；其他格式轉 NULL 並記錄問題 |
| height | height_cm | smallint | 正整數且在型別範圍內才轉換；空字串轉 NULL；其他值轉 NULL 並記錄問題 |
| wikidata_id | wikidata_id | text | 符合 Q 加正整數的格式才保存；空字串轉 NULL；其他值轉 NULL 並記錄問題 |

### 格式通過不代表內容已確認

- IOC 格式通過不代表已驗證為正式代碼；例如 UNK 不自動對應國家。
- 身高低於 100 或高於 250 公分，保留可解析的數值並標記待查；
  未確認前排除於身高分析，不因此排除球員或整場比賽。
- U 是來源的未知慣用手代碼，與空白分開保存。
- Unknown、X X 等名稱保留來源並標記，不當成一般真人累計統計。
- 部分姓名含 unknown 不直接判為共用占位球員。
- 生日格式有效仍可能與比賽時間矛盾，需另做跨資料檢查。

## 比賽識別欄位對照（設計草案）

來源比賽以 (tour, tourney_id, round, match_num) 識別。
目前快照已通過此鍵的非空與轉換後唯一性檢查；未來更新仍需驗證。

| 來源欄位 | 正式欄位 | 型別方向 | 轉換與品質規則 |
| --- | --- | --- | --- |
| 檔案所屬 atp/wta | tour | varchar(3) | 轉為 ATP/WTA，必填 |
| tourney_id | tourney_id | text | 必填，保留來源字串，不從名稱重建 |
| round | round | text | 必填，保留來源代碼，不轉成顯示用中文 |
| match_num | match_num | integer | 必填，須可轉為 integer；不自行重新編號 |
| tourney_date | tourney_date | date | 必填，有效 YYYYMMDD 轉日期；不強制與檔名年份一致 |
| winner_id | winner_id | integer | 必填正整數，以 (tour, winner_id) 對照球員 |
| loser_id | loser_id | integer | 必填正整數，以 (tour, loser_id) 對照球員 |

### 識別與參照異常

- 必填欄位缺少或無法轉換時，隔離來源紀錄並記錄原因，不補假值。
- 找不到球員時保留來源並隔離待查，不自動建立一般球員資料。
  這是對原規格「自動補佔位球員」的修訂方向，尚未實作。
- 勝敗方 ID 相同時保留來源並標記身分問題，不進入預設個人勝負、H2H 或 Elo。
- 同一來源鍵再次出現時，比較內容：一致屬重複，不同屬衝突。
  同一快照內衝突與跨快照更新須分開處理，不能直接覆寫；具體機制另行設計。
- tourney_date 是來源賽事日期，不視為每場比賽的實際比賽日期。
- 未見過的非空 round 代碼保留並標記待查，不猜測替換。

## 比賽其餘欄位對照（設計草案）

以下 `winner_*`、`loser_*` 各自對應勝方及敗方，不以現在的球員資料覆蓋比賽當時來源值。
選填欄位空字串轉 NULL；無法轉換時保留來源並記錄問題，不默默截斷或四捨五入。

| surface | surface | text | 保留來源代碼；未知代碼待查，不猜成 Hard 等類別 |
| draw_size | draw_size | smallint | 正整數才轉換；exho 等非數字轉 NULL 並記錄問題 |
| tourney_level | tourney_level | text | 保留 A、PM、T1、50+H 等原碼；分析分類另外保存 |
| winner_seed、loser_seed | 同名欄位 | text | 保留 1F、ALT、LL、Q、WC 等文字；第一版不新增推測的數值種子 |
| winner_entry、loser_entry | 同名欄位 | text | 保留原碼；不把文字種子搬進此欄 |
| winner_rank、loser_rank | 同名欄位 | integer | 正整數；無效值轉 NULL 並記錄問題 |
| winner_rank_points、loser_rank_points | 同名欄位 | integer | 非負整數，零保留；無效值轉 NULL 並記錄問題 |
| winner_age、loser_age | 同名欄位 | numeric(4,1) | 僅原樣可表示時轉換；非正值保留數值並排除年齡分析，另做身分檢查 |
| winner_ht、loser_ht | winner_height_cm、loser_height_cm | smallint | 正整數且可表示；100～250 以外保留數值並標記，排除身高分析 |
| winner_name、loser_name | 來源紀錄 | 字串 | 保留比賽時姓名供追查，不作外鍵，也不覆寫球員主檔 |
| winner_hand、loser_hand | 來源紀錄 | 字串 | 第一版不重複存入正式比賽欄位；不覆寫主檔 |

| score | score | text | 原樣保存；不修復 7-Oct、6-36-3 等可疑字串 |
| best_of | best_of | smallint | 已知 1、3、5 保留；其他值保留來源、正式欄位 NULL 並待查 |
| minutes | minutes | smallint | 可表示的非負整數；零值保留但不作時間分析樣本；負值／無法轉換轉 NULL |

球員主檔只表示來源目前提供的基本資料，不能當成歷史國籍或歷史姓名的完整紀錄。
極端分鐘數依已查出的紀錄標記待查，未定通用上限，不新增任意刪除門檻。
比賽身高正式欄位是本輪新增的設計方向，用於區分比賽來源值與主檔值。

下表每個來源後綴各套用 `w_` 與 `l_`，共 18 欄；正式型別方向皆為 smallint。

| 來源後綴 | 正式後綴 | 意義 |
| --- | --- | --- |

| svpt | svpt | 發球分數 |
| 1stIn | 1st_in | 一發進球數 |

可表示的整數保留，包括已發現的 -4、-6；負值加品質問題，不能用於相關指標。

## 排名欄位對照（設計草案）

| 來源欄位 | 正式欄位 | 型別方向 | 規則 |
| --- | --- | --- | --- |
| 檔案所屬 atp/wta | tour | varchar(3) | ATP/WTA，必填 |
| ranking_date | ranking_date | date | 必填，八位 ASCII 數字且日期有效 |
| player | player_id | integer | 必填正整數，須參照同巡迴球員 |
| rank | rank | integer | 必填正整數；允許不同球員同名次，不以排名作唯一鍵 |
| points | points | integer | 可空，非負整數，零不是缺值 |
| tours（僅 WTA） | source_tours | integer | 可空，非負整數；ATP 為 NULL，不作完整參賽次數分析 |

唯一鍵維持 (tour, ranking_date, player_id)。必填或參照錯誤隔離來源紀錄。
非空 points/source_tours 無法轉換時先隔離該列，避免把異常轉成 NULL 後誤判為內容一致。
同快照依轉換後 rank、points、source_tours 比較；一致重複合併但保留所有來源位置。
rank 或 points 不一致整組隔離；不採檔案順序或挑較高名次。
只有 tours 不同目前沒有案例；未來發生先整組待查，不自動選值，正式取捨另定。
不補造沒有發布紀錄的日期，也不把前一次排名當成新一期來源紀錄。

## 來源、正式資料與品質的保存責任

以下為邏輯結構，名稱與實際資料表配置待 SQL 教學時確認。
不表示每一列都一定需要獨立資料表。

| 結構 | 保存內容 | 識別／關聯 |
| --- | --- | --- |
| 來源快照 | 儲存庫、Git SHA、取得時間、檔案清單 | 快照識別碼 |
| 來源檔案 | 相對路徑、SHA-256、標頭、紀錄數 | 快照與相對路徑 |
| 匯入執行 | 狀態、開始／結束時間、轉換與品質規則版本、錯誤摘要 | 來源快照與執行識別碼 |
| 來源紀錄 | 原始欄位字串、資料紀錄序號、資料種類 | 來源檔案與紀錄序號 |
| 正式資料 | players、matches、rankings 的型別化欄位 | 各自業務鍵；matches 另保留內部 id |
| 來源對照 | 正式紀錄對應的所有來源紀錄 | 支援多個一致重複列對應同一正式列 |
| 品質問題 | 規則代碼、版本、欄位／角色、原因、影響指標、處理狀態 | 匯入執行及來源紀錄；正式資料可能尚不存在 |
| 賽事判斷 | 納入狀態、分析系列、命中規則、理由與證據 | 規則版本、快照、tour 與 tourney_id |

第一版先以不可變 CSV 快照及來源位置作為原始資料的權威紀錄。
資料庫是否再完整存每列 JSON 尚未定案：排名超過五百萬列，須先評估磁碟及備份成本。
無論選擇哪種配置，隔離列與一致重複列都必須能還原所有原值與來源位置。
CSV 必須作為可恢復的資料資產備份，不能只依賴外部 Git 儲存庫將來仍可下載。
如使用解析後 JSON，欄位值保留字串、空字串不提前轉 NULL；它不取代原 CSV 位元組與雜湊。

品質問題不可只有一個 is_valid 布林值：同一列可同時有生日、身高及發球問題，
影響範圍不同。缺值不必為每個空欄產生問題列；依欄位需求判定樣本是否有效。
尚未判斷或規則未實作，不能被解讀為「已通過」。

## 隔離與查詢資格

- 無法建立合法識別鍵、缺少必要參照或排名衝突：保存來源及隔離原因，不進入正式可查詢資料。
- 身分疑點：保留可解析紀錄與追溯資訊，預設個人統計排除；實際落在候選表或正式表的配置待定。
- 欄位異常：允許其他有效用途，相關指標排除；例如身高異常不影響已確認的勝負。
- 賽事範圍 REVIEW/EXCLUDE：不是格式錯誤，保留來源及分類理由。
- 對外資料只使用成功發布的同一批次；還要符合賽事範圍、身分條件與該指標規則。

本輪不計算新的「最終可匯入筆數」。此前排名預期值只涵蓋既有重複／衝突規則，
不代表已套用此文件全部規則的結果。

## 重複執行與跨快照更新

1. 相同快照、相同檔案內容與相同規則版本再次執行，結果應一致，不能多出重複正式資料。
2. 同一路徑但雜湊不同視為輸入改變，不沿用舊成功紀錄；標示快照不一致並停止查明。
3. 失敗批次保留錯誤紀錄，可重試；尚未完成的資料不對外發布。
4. 同快照內出現同鍵不同內容屬衝突；新快照改變舊鍵內容是來源修訂候選，先產生差異報告。
5. 新快照需比對新增、修改及不再出現的鍵。來源未出現不等於應直接刪除；需先確認輸入檔案範圍一致。
6. 第一版先做完整快照驗證與明確發布，不做自動逐列覆蓋；實際切換及失敗回復機制在匯入實作前確認。
7. 規則版本改變也需要重新驗證受影響資料；舊快照與舊結果的關聯不可被改成新版本。

## 原規格調整清單

原規格第 6 節 SQL 為早期草案，不直接執行。本輪設計相較該草案的差異：

- winner_seed、loser_seed 改以 text 保存文字種子。
- 增加比賽來源身高與排名 source_tours 的保存方向。
- 補上來源、匯入執行、品質問題、賽事判斷及來源對照的保存責任。
- 找不到球員先隔離，不自動新增一般佔位球員。
- 不用資料庫單一非負限制取代欄位品質規則；不假設所有資料都可直接公開統計。
