# 視覺化與資料瀏覽修正（2026-10-31）

使用者回報圖表太扁、Elo小數遮住圖、表格不能排序、空白姓名自動查詢及賽事明細顯示球員ID。本輪依現有排版修正，依使用者授權提交，未推送或部署；既有 `.vscode/settings.json` 未修改。

## 行為修正

- 球員索引原本以 `enabled: search.valid` 啟動查詢，空白姓名也是合法條件，因此會讀取全部球員，包含來源姓名缺漏者。現在初次進頁／清空條件只顯示輸入提示；姓名非空並送出後才查詢。帶姓名的分享網址仍會正常查詢，不任意修改或刪除來源球員。
- 球員觀測散點圖高度420～600px；六角圖限制最大寬820px，高480～760px，避免全寬但高度不足導致分箱被壓扁。手機仍使用響應式寬度，資料座標及分箱算法不變。
- Elo目前值與Y軸顯示整數。折線保留原始浮點計算值；Y軸文字靠右置於獨立區域，繪圖左界由30移至60，不讓長標籤遮住線條。
- 賽事明細在同一SQL依 `(tour, player_id)` JOIN雙方姓名，前端顯示姓名及球員連結，不逐筆呼叫球員API。標題顯示賽事名稱，不直接印賽事ID。
- 球員索引、基本資料、觀測表、tooltip與hover提示不顯示球員編號；Elo不顯示模型編號，研究CSV不輸出球員／匯入批次ID。ID繼續用於內部關聯、React key及網址；來源快照、規則版本與作者授權仍保留以供追查。

## 所有表格的排序

共用 SortableTable，以按鈕操作欄名，第一次升冪、再按降冪，提供方向箭頭、鍵盤焦點及 aria-sort。數字／百分比採數值排序，出生與比賽日期用原始日期鍵；缺值固定置後，同值維持原順序，沒有改寫來源或把缺值補零。

- 遠端分頁：球員索引、排名歷史、比賽歷史、賽事索引／明細，明示「本頁排序」。只重排目前API頁面，其他頁保持來源順序；不宣稱已對整個遠端結果排序，也不為排序下載全部排名／比賽。
- 已載入的完整或有界集合：指定日期排名、球員比較、H2H分組、球員分析、年齡統計、場地／慣用手、相關矩陣、箱型摘要與六角計數，都可依欄名排序。
- 散點資料表與賽季場地表：先對整個已選集合排序，再做每頁50筆的前端分頁；改排序回第一頁。上限外省略的資料不會因此加入。

複合欄位依主要值排序，例如樣本／分母依分母、箱型鬚依下界、離群值依數量。CSV保留所選來源集合與原始順序，畫面排序不修改選樣規則。

## 後續補正：首頁圖表、舊後端辨識與姓名搜尋

- 首頁 `/tennis/visualizations` 的散點圖另有元件，已補上420～600px高度；進階工作台配對矩陣補上480～640px高度。不是只調整研究頁散點圖。瀏覽器測試直接檢查這兩張圖的實際高度。
- 查核目前8081服務的真實HTTP回應，只有winner_id／loser_id等舊欄位，沒有winner_name／loser_name；正在執行的Java程序早於先前SQL修改啟動。原始球員姓名沒有遺失，問題是後端尚未重啟載入新版。新增前端契約辨識：回應缺少姓名欄位時明示「請重新啟動後端服務」，不再把不存在的欄位說成球員姓名未提供。隔離容器中的新版姓名與連結測試持續通過。
- H2H與球員比較的所有可見球員ID輸入改為姓名搜尋選取。使用同巡迴既有球員搜尋API、300ms debounce、最多10筆候選，顯示姓名／巡迴／IOC／生日以協助區分同名者。支援方向鍵、Enter、Escape、滑鼠與combobox/listbox語意；空白不搜尋，編輯已選姓名會清除身分，必須重新選取。
- H2H選兩位不同球員；比較選2～4位不同球員。切換巡迴清空已選者，不能沿用另一巡迴的相同ID。未選候選或重複者不送出分析請求。
- URL／API繼續用內部識別維持舊書籤；開啟舊網址時，輸入框自動解析姓名，不把ID放進文字框。H2H結果另外列出已套用的巡迴與姓名，避免尚未送出的篩選變更被誤認為目前結果。表頭維持單行，由表格容器處理手機橫向捲動。
