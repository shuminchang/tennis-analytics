# 網球統計網站｜規格與開發文件

版本 v0.1｜2026-10-23｜資料來源：Jeff Sackmann（CC BY-NC-SA 4.0）

## 1. 專案概述

目標：以 tennis-sackmann-archive 的 ATP、WTA 與四大滿貫逐分資料，建立可瀏覽、可視覺化的網球統計網站，部署在 https://www.shuminapp.com/tennis，同時作為 React、Spring Boot、PostgreSQL 的逐步教學專案。

已確認的決議：

| 項目 | 決議 |
| --- | --- |
| 伺服器 | Linode Nanode：1 vCPU、1 GB RAM、25 GB 儲存、無額外 Volume |
| Web server | Apache 2，路徑 /tennis |
| 後端 | Spring Boot 3.x（Java 21，以建立專案時最新穩定版為準） |
| 資料庫 | PostgreSQL 16 以上，與應用同機 |
| 前端 | React + Vite + TypeScript |
| 資料範圍 | ATP 與 WTA 皆納入；四大滿貫逐分資料列為後期選做 |
| 資料更新 | 手動 |
| 語言 | 繁體中文與英文雙語 |
| 權限 | 訪客、會員、進階、管理員四級 |

非目標：商業化（廣告、收費）、博弈用途的預測、即時比分。

## 3. 資源預算（1 GB RAM 是最大限制）

預估記憶體分配（需用 free -m 與 ps 實測後修正）：

| 元件 | 預估 |
| --- | --- |
| OS 與系統服務 | 約 150 MB |
| Apache（event MPM） | 約 50–100 MB，取決於 shuminapp.com 現有網站的實作方式 |
| PostgreSQL | 約 200–250 MB |
| Spring Boot JVM | 約 350–450 MB（堆積上限 256 MB） |

合計接近上限，因此採以下原則：

1. 伺服器上不建置：Gradle/Maven 與 npm build 都在本機或 GitHub Actions 完成，只上傳 jar 與 dist。
2. 重運算預先算好：Elo、彙總表在匯入後一次算完，查詢時只讀結果。
3. 每個查詢都要有索引、分頁上限與逾時。
4. 使用 Caffeine 記憶體快取熱門查詢，資料只在手動匯入時變動，匯入後清快取。
5. 不安裝重型監控；日誌用 logrotate 輪替。
6. 建立 2 GB swapfile，vm.swappiness 設為 10。
7. 效能目標：一般 API p95 低於 500 ms，H2H 低於 1 秒。若 swap 長期大量使用或達不到目標，再升級方案。

磁碟（25 GB）：逐分資料體積大，匯入前先用 du -sh 評估。第一版不把原始逐分 CSV 放上伺服器，改為本機彙總後只載入彙總表。原始 CSV 也不必留在伺服器，只保留匯入需要的檔案或直接在本機匯入後用 pg\_dump 搬移。

## 5. 資料說明

以 repo 實際檔名與 data\_dictionary 為準，匯入前先核對欄位。

| 來源 | 內容 | 第一版 |
| --- | --- | --- |
| atp\_players、wta\_players | 球員基本資料（姓名、慣用手、生日、國籍、身高） | 匯入 |
| atp\_matches\_YYYY、wta\_matches\_YYYY | 主巡迴比賽結果與發球統計 | 匯入 |
| **rankings**（依年代分檔） | 週排名 | 匯入 |
| qual\_chall、futures 系列 | 資格賽、挑戰賽、Futures | 暫不匯入 |
| slam\_pointbypoint 的 matches 與 points | 四大滿貫逐分紀錄（2011–2024） | 後期，只載入彙總 |

資料品質注意事項：

- 早期年份的統計欄位多半缺漏，圖表與比率計算要排除空值。
- 球員一律用 (tour, player\_id) 識別，不用姓名比對。ATP 與 WTA 的 ID 分開管理。
- tourney\_date 是賽事開賽日，同一賽事的比賽日期相同，需用輪次排序。
- 比分含 W/O（不戰而勝）、RET（退賽）、DEF，統計時要定義處理規則。
- 日期欄位為 YYYYMMDD 整數，匯入時轉為 date。

## 6. 資料模型

```sql
CREATE TABLE players (
  tour varchar(3) NOT NULL CHECK (tour IN ('ATP','WTA')),
  player_id integer NOT NULL,
  name_first text, name_last text,
  hand char(1), dob date, ioc char(3), height_cm smallint, wikidata_id text,
  PRIMARY KEY (tour, player_id)
);

CREATE TABLE matches (
  id bigserial PRIMARY KEY,
  tour varchar(3) NOT NULL,
  tourney_id text NOT NULL,
  tourney_name text, surface text, draw_size smallint, tourney_level text,
  tourney_date date NOT NULL, match_num integer NOT NULL,
  winner_id integer NOT NULL, loser_id integer NOT NULL,
  winner_seed smallint, winner_entry text, winner_rank integer,
  winner_rank_points integer, winner_age numeric(4,1),
  loser_seed smallint, loser_entry text, loser_rank integer,
  loser_rank_points integer, loser_age numeric(4,1),
  score text, best_of smallint, round text NOT NULL, minutes smallint,
  w_ace smallint, w_df smallint, w_svpt smallint, w_1st_in smallint,
  w_1st_won smallint, w_2nd_won smallint, w_sv_gms smallint,
  w_bp_saved smallint, w_bp_faced smallint,
  l_ace smallint, l_df smallint, l_svpt smallint, l_1st_in smallint,
  l_1st_won smallint, l_2nd_won smallint, l_sv_gms smallint,
  l_bp_saved smallint, l_bp_faced smallint,
  UNIQUE (tour, tourney_id, round, match_num),
  FOREIGN KEY (tour, winner_id) REFERENCES players (tour, player_id),
  FOREIGN KEY (tour, loser_id) REFERENCES players (tour, player_id)
);

CREATE INDEX ix_matches_winner ON matches (tour, winner_id, tourney_date);
CREATE INDEX ix_matches_loser  ON matches (tour, loser_id, tourney_date);
CREATE INDEX ix_matches_h2h    ON matches (tour, winner_id, loser_id);
CREATE INDEX ix_matches_tourney ON matches (tour, tourney_id);

CREATE TABLE rankings (
  tour varchar(3) NOT NULL, ranking_date date NOT NULL,
  rank integer NOT NULL, player_id integer NOT NULL, points integer,
  PRIMARY KEY (tour, ranking_date, player_id)
);
CREATE INDEX ix_rankings_player ON rankings (tour, player_id, ranking_date);
```

欄位型別以實際資料驗證後調整。若比賽中出現 players 表沒有的球員，匯入時補一筆佔位球員。

其他資料表（以 Flyway 管理）：

| 資料表 | 用途 |
| --- | --- |
| elo\_history | 每場比賽後雙方的整體 Elo（match\_id、player\_id、before、after） |
| elo\_current | 每位球員目前的整體與分場地 Elo |
| users | 帳號、密碼雜湊、角色、啟用狀態、建立與最後登入時間 |
| invites | 邀請碼、角色、到期時間、是否已使用 |
| audit\_log | 登入、權限拒絕、管理操作紀錄 |

H2H 查詢範例（教學用）：

```sql
SELECT winner_id, count(*) AS wins
FROM matches
WHERE tour = :tour
  AND ((winner_id = :a AND loser_id = :b) OR (winner_id = :b AND loser_id = :a))
  AND (:surface IS NULL OR surface = :surface)
  AND score NOT LIKE '%W/O%'
GROUP BY winner_id;
```

## 7. 資料匯入規格

因為手動更新，匯入程式必須可重複執行：

1. 以獨立的 Spring Boot profile（import）執行命令列匯入，不常駐。
2. 使用 PostgreSQL COPY（JDBC 的 CopyManager）串流寫入暫存表，再用 INSERT ... ON CONFLICT DO UPDATE 合併到正式表，避免用 JPA 逐筆寫入造成記憶體與時間浪費。
3. 匯入順序：players、matches、rankings，最後重建彙總表與 Elo。
4. 匯入後驗證：筆數、日期範圍、孤立外鍵、關鍵球員抽樣核對。
5. 建議在本機匯入並驗證，再用 pg\_dump -Fc 搬到伺服器 pg\_restore；上游資料更新時重複同流程。
6. 匯入完成後清除快取（重啟應用或呼叫管理端點）。

## 9. 功能清單與發布評估

| 功能 | 價值 | 發布 | 權限 |
| --- | --- | --- | --- |
| 球員檔案（生涯勝率、冠軍數、分場地勝率） | 高 | 發布 | 公開 |
| 排名走勢（多人疊圖） | 高 | 發布 | 公開 |
| 歷屆賽事冠軍與賽果 | 高 | 發布 | 公開 |
| 分場地表現比較 | 高 | 發布 | 公開 |
| 發球統計雷達圖 | 中高 | 發布 | 公開或會員 |
| 年齡曲線（巔峰年齡） | 中 | 發布，加註樣本限制 | 會員 |
| 對戰紀錄與勝率（H2H） | 高 | 發布，顯示場數與信賴區間 | 進階 |
| Elo 評分與走勢 | 高 | 發布，說明演算法 | 進階 |
| 左右手、身高與勝率 | 中低 | 有條件發布，註明相關不等於因果 | 進階 |
| 逐分彙總（關鍵分、破發點轉換） | 中 | 後期 | 進階 |
| 比賽勝率估計 | 中 | 後期，僅作統計估計 | 進階 |
| 史上最強排行 | 爭議高 | 不發布，或只做明確定義的 Elo 排行 | 無 |
| 排名與年齡相關性 | 低 | 不發布 | 無 |

H2H 規格：同時顯示總場數、各自勝場、分場地與分年份勝負；場數小於 5 時顯示「樣本過少」提示；勝率附 Wilson 信賴區間；比賽時間範圍可篩選；W/O 預設排除。

Elo 規格（可調整，需用自己的資料驗證）：初始 1500；勝率期望 1 / (1 + 10^((Rb − Ra) / 400))；變動 K 值，隨已賽場數遞減（常見形式 K = 250 / (n + 5)^0.4）；分場地 Elo 另算，顯示時可與整體 Elo 加權；比賽依 tourney\_date、輪次、match\_num 排序；W/O 排除，RET 納入；預先計算並存入 elo\_history。

## 10. 權限與帳號

| 角色 | 內容 |
| --- | --- |
| GUEST | 公開頁面瀏覽 |
| MEMBER | 球員比較、收藏 |
| ADVANCED | H2H、Elo、進階統計 |
| ADMIN | 帳號管理、快取清除、匯入狀態 |

- 採 Spring Security Session + Cookie；教學後期再單獨介紹 JWT 的取捨。
- 後端以 @PreAuthorize 檢查角色，前端只負責隱藏與導向，不作為安全邊界。
- 不開放自由註冊：由管理員開通或邀請碼註冊。
- Session 先存記憶體（單機），重啟會登出；之後再評估 Spring Session JDBC。

## 12. 資安規格

| 威脅 | 對策 |
| --- | --- |
| 網路暴露 | 防火牆只開 80、443、SSH；PostgreSQL 與 Spring Boot 只綁 127.0.0.1 |
| SSH 入侵 | 關閉密碼登入、只用金鑰、fail2ban |
| 傳輸安全 | Let's Encrypt、HTTP 轉 HTTPS、HSTS（先用短效期再拉長） |
| SQL Injection | JPA 與參數化查詢，不拼接 SQL，搜尋參數特別注意 |
| XSS | React 預設跳脫；禁用 dangerouslySetInnerHTML；Apache 設 CSP |
| CSRF | 啟用 Spring Security CSRF（CookieCsrfTokenRepository）；Session Cookie 設 HttpOnly、Secure、SameSite=Lax |
| 密碼 | BCrypt 或 Argon2；最小長度檢查 |
| 暴力登入 | 5 次失敗鎖定 15 分鐘；登入端點限流 |
| 資源耗盡 | 每人與每 IP 速率限制（Bucket4j）；分頁上限；statement\_timeout；進階端點併發限制 |
| 機密外洩 | 密碼與金鑰放 EnvironmentFile（權限 600），不進 Git |
| 資訊洩漏 | 關閉對外 Actuator 與正式環境 Swagger；不回傳 stack trace |
| 與主站互相影響 | Session Cookie Path 設 /tennis，不設 Domain；Cookie 名稱與主站區分 |
| 相依套件 | Dependabot、npm audit、OWASP Dependency-Check |
| 資料遺失 | 每日 pg\_dump 備份至外部儲存，定期演練還原 |
| 稽核 | audit\_log 記錄登入與權限事件，不記錄密碼與完整 Cookie |

## 13. 部署規格

### 13.1 Apache（/etc/apache2/conf-available/tennis.conf）

需啟用 proxy、proxy\_http、headers、rewrite 模組。

```apache
Alias /tennis /var/www/tennis/dist

<Directory /var/www/tennis/dist>
    Require all granted
    Options -Indexes
    FallbackResource /tennis/index.html
</Directory>

ProxyPreserveHost On
ProxyPass        /tennis/api http://127.0.0.1:8080/tennis/api
ProxyPassReverse /tennis/api http://127.0.0.1:8080/tennis/api
RequestHeader set X-Forwarded-Proto "https"

<Location /tennis>
    Header always set X-Content-Type-Options "nosniff"
    Header always set Referrer-Policy "strict-origin-when-cross-origin"
    Header always set Content-Security-Policy "default-src 'self'; img-src 'self' data:; style-src 'self' 'unsafe-inline'; frame-ancestors 'none'; base-uri 'self'; form-action 'self'"
</Location>

<LocationMatch "^/tennis/assets/">
    Header set Cache-Control "public, max-age=31536000, immutable"
</LocationMatch>
```

React build 設定 base 為 /tennis/；index.html 不設長快取。
